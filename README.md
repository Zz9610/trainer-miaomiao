# 骑行台妙妙工具

> 为了方便自己使用而写的骑行台妙妙工具。
> 基于 **FTMS**（Fitness Machine Service，蓝牙 0x1826）标准，浏览器界面 + 本地 Python 服务，
> 蓝牙由后端直接操作（不依赖 Web Bluetooth）。
> 已在 **Magene T110** 上完整验证，理论上适用于任何实现 FTMS 的 BLE 骑行台。
> 文中出现的设备与厂商名称仅用于说明兼容性，不表示存在任何关联、授权或认可。

---

## 功能

| 模块 | 说明 |
|---|---|
| **ERG 恒功率** | 踩快踩慢，骑行台自动调节阻力把功率稳定在目标值（每 800ms 下发一次） |
| **坡度模拟** | −20% ~ +25%，模拟上下坡的路感 |
| **路线回放** | 导入 FIT / GPX 轨迹，按真实地形起伏自动变坡度；速度由功率反推 |
| **实时数据** | 功率 / 踏频 / 心率，含最大、平均、最近 5 分钟曲线与全程概览 |
| **训练计划** | 多段计时课程（如 5 分钟 90W → 10 分钟 130W），自动逐段切换 |
| **骑行记录** | 结束自动保存，含 NP / IF / TSS / 卡路里；可查看历史曲线 |
| **自动暂停** | 停止踩踏 3 秒自动暂停计时，继续踩自动恢复 |
| **设备记忆** | 记住已连接设备的 MAC，下次一键连接 |

支持同时连接：骑行台 + 心率计（0x180D）+ 踏频计（0x1816）。

## 快速开始

### 环境

- Windows 10 / 11
- Python 3.9+（[下载](https://www.python.org/downloads/)，安装时勾选 *Add python.exe to PATH*）
- 蓝牙适配器（BLE 4.0+）

### 运行

```
双击  start.bat
```

或手动：

```bash
python server.py
```

浏览器会自动打开 `http://localhost:8000/index.html`。

> `vendor/` 里已经内置了 `bleak` 及其依赖（约 2 MB），**不需要 pip install**。
> 想用自己的环境也可以：`pip install bleak`

### 基本流程

1. 点「连接 骑行台」→ 从扫描到的设备里选你的骑行台
2. 连上后会自动完成初始化（设备特定序列），状态变绿
3. 踩起来 → 点「开始」
4. 拖滑块调目标功率，或切换到「坡度模拟」/「路线模拟」
5. 骑完点「结束骑行」，自动结算并保存记录

## 数据存储

所有数据是**本地 JSON 文件**，存放在 exe / 脚本同级的 `data/` 目录：

```
data/
├── profile.json    个人资料（身高/体重/FTP）
├── rides.json      骑行记录（含曲线）
├── plan.json       训练计划
├── devices.json    已记住的蓝牙设备
└── snapshot.json   断点快照（异常中断时才有）
```

可以直接用记事本打开、复制备份、删除。

## 技术要点

### 架构

```
浏览器页面 ──HTTP/SSE──► server.py ──bleak (WinRT)──► BLE 骑行台
```

蓝牙完全由后端进程执行，因此：

- 刷新页面不会断连
- 手机 / 平板通过局域网访问也能控制（只是显示终端，不需要蓝牙权限）
- iOS 也能用（Safari 不支持 Web Bluetooth，但这里只是普通 HTTP）

### 主要协议

- **ERG**：`0x05` + 目标功率（uint16 小端，单位 1 W）
- **坡度**：`0x11 00 00 <grade_lo> <grade_hi> 28 33`（grade 单位 0.01%）
- **控制权**：先发 `0x00`（Request Control），再 `0x07`（Start/Resume）
- **停止**：`0x08 0x01`

协议细节通过公开的 FTMS 规范 + 对设备实际通信的观察得到。

### 已知设备特性

部分设备（包括 T110）在连接约 11 分钟后会进入「停止测量」状态：`2AD2` 帧仍在推送，但功率字段被清零、其余字段冻结。
仅靠周期心跳无法维持，需要重新下发初始化序列。本工具内置了 **4 分钟周期续期 + 冻结看门狗** 来规避。
